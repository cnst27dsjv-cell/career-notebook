# 面试练习与 Obsidian 笔记

## 调研、练习和复盘

1. 在「面试准备」打开一个准备条目，点击「调研并模拟面试」。选择要参考的资料，按需使用关联简历正文。
2. 联网调研只向搜索服务提交公司、岗位和轮次。生成题目时，文本模型会使用所选资料、JD、简历正文和搜索摘要。搜索摘要会显示来源，不代表已核实网页全文。
3. 核对来源并编辑题目后开始。也可以不联网，仅根据岗位和所选资料练习；这类题目不是公司原题。
4. 回答自动保存，可获取反馈、建议稿及追问。结束时生成整场复盘，之后可从准备条目的会话列表继续查看。
5. 可以确认新建结构化问答，或给已有问答追加回答版本。回答与点评分别保存，原始文档不会被练习答案覆盖。旧格式资料仍支持更新并保留修订记录。会话也会保留之前的回答、反馈及复盘。
6. 整场记录可下载为 Markdown，放入 Obsidian。

搜索或模型失败时，已保存的来源和回答仍保留，可重试或不联网继续。显示保存失败时，应先重试保存，避免关闭页面。

## 不开通 Sync 也能连接本机笔记

电脑 Chrome 中打开本地工作台，进入「面试准备」或资料库的「连接 Obsidian / 导入 Markdown」。点击「选择本机笔记文件夹」，选中 Obsidian 库里的面试笔记子文件夹即可。部署后的 HTTPS 网站在支持的浏览器中也可以由用户主动选择本地文件夹；云端服务本身不能直接访问电脑硬盘。

- 首次选择只列出 Markdown 文件；勾选后预览正文，确认导入才保存到工作台账号。
- 导入的记录进入「原始文档」，可逐篇拆分整理，也可在下一次练习前直接勾选作为参考。模型上下文会限制长资料的长度，界面会提示截断；账号中保存的笔记仍保留导入全文。
- 同一库请保持库名称和所选根文件夹一致。通过库名称及相对路径识别同一篇笔记，相同内容重复导入不会再新建。
- 网页上确认了新内容后，重新选择并预览同一篇笔记，核对网站版本和本地版本，再点击写回并授权。两端版本冲突会要求重新预览，不会静默覆盖。
- 文件夹连接仅保留在当前页面使用期间。刷新或重新进入后需重新选择；这不是后台双向自动同步。
- 不支持文件夹选择的浏览器仍可导入 `.md` 文件，但不能直接写回，需要下载后自行保存。
- 不会自动跟随双向链接或读取图片、PDF 等附件。单次最多导入 30 篇；建议选择面试子文件夹，而非整个大型库。

无需安装 Obsidian 插件或付费 Sync。此次实现的是用户主动操作的笔记交换；跨电脑自动同步本地 Obsidian 库不在本次范围。

上线前应在正确的生产数据库环境执行项目已有的 `npm run db:migrate`，再部署新代码。不能把本地数据库地址或 API key 提交到 Git。调研使用现有 Tavily 配置；模拟面试使用现有默认文本模型配置，DeepSeek 的交互请求关闭额外推理以减少等待。

```sh

npx tsx --env-file=.env scripts/interview-library-check.ts
npx tsx --env-file=.env scripts/interview-browser-check.ts

```

两个集成脚本使用本地测试数据库及临时数据，并在结束时清理；浏览器验收模拟 AI 响应。另已使用合成回答完成真实 Tavily 与 DeepSeek 连通测试。个人 Obsidian 库的系统文件夹授权与实际写回仍需在用户选定库后验收。

## 助理自动查阅已导入笔记

将 Obsidian 面试笔记导入资料库后，可以直接在「我的助理」提问，例如“帮我梳理华泰资管的 ABS 项目经历”，不必每轮重新勾选笔记。助理会根据当前问题及最近对话检索未归档的账号资料，并读取相关正文或节选。长笔记会优先截取命中段落，而非只读取开头。

回复下的「本次自动查阅的笔记」可展开查看标题、版本、来源和实际提供给模型的内容。这里表示本轮读取范围，不表示笔记事实已核实；待确认的导入记录仍需要你核对。更新资料后下一轮使用新版，旧回复保留当时的引用快照。

目前采用中文关键词检索，每轮最多六篇，找不到时可补充公司、岗位或项目名称；它并非全库语义搜索。只访问已导入账号的副本，不会自动扫描、同步或修改电脑上的 Obsidian 文件夹。资料库修改和日程等操作仍需原有确认流程。


## 把原始资料整理成练习库

- **原始文档**：完整保留导入的 Obsidian、Word 或粘贴文字，显示未整理/整理中/已整理及已入库条目数。
- **练习库**：按「面试问答」「经历素材」「知识与调研」查看已确认内容；支持按岗位与关键词筛选。问答内的回答版本、背景介绍、其他智能体建议分别显示。
- **旧资料**：保留以前的分类和内容。整篇混合资料可以点击「移至原始文档并拆分」，不删除原文。

进入原始文档，点击「AI 拆分本次原文」。左侧核对原文，右侧编辑候选；点击定位可高亮原文依据。没有个人回答的题目允许留空，不把 AI 的建议稿当个人经历。长文超过 24000 字时自动分段，默认选中第一段；核对并入库当前候选（或移除不需要的候选并保存）后，在「选择整理段落」切换下一段继续。也可展开查看并调整本次发送给 AI 的连续原文。原文始终保留全文，重新打开时默认回到第一段，请自行选择要继续的段落。按钮不可用时，下方会说明原因。

可以手动添加、拆分或合并内容，再移除多余候选。勾选想保存的条目，点击「确认选中条目入库」；剩余内容保存为草稿，下次继续。若已有同一道题，可在保存方式中选择它，追加一版回答。处理完后可「标记整理完成」，未选内容仍在原文中。

AI 候选自动保存为草稿；手动编辑需点击「保存整理进度」或确认入库。关闭有未保存修改的弹窗会提醒。浏览器直接关闭或整页刷新前请先保存。

修改或重新导入原文会清除旧拆分草稿与完成标记，已经确认入库的条目不受影响，仍保存当时的来源版本和原文片段。整理条目的修改不会自动改写原始文档或本机 Obsidian。

新增迁移 `20261016110000_library_organization` 为 Material 添加 format/structure 字段；只在本地执行。上线前需执行全部未部署迁移，再发布代码。

新增验证：`npx tsx --env-file=.env scripts/library-organizer-check.ts`（真实本地数据库），`npx tsx --env-file=.env scripts/library-organizer-browser-check.ts`（真实 Chrome 界面与 API，AI 输出使用合成响应）。
