# Workers 免费版保存性能优化

**Goal:** 降低投递/日程保存的 CPU 消耗，保持免费方案和数据一致性。
**Architecture:** 先在本地 Workers 运行时建立保存场景基线，用采样确定热点；只优化测量证实的重复工作，再对相同场景复测。
**Tech Stack:** Workers、vinext、Prisma PostgreSQL adapter、Vitest。
**Spec:** 用户 2026-10-20 选择“保持免费，先做性能优化并验证效果”。

## Constraints
- 不升级套餐，不修改用户现有业务记录，不削弱认证和事务。
- 不跨请求复用 Workers 数据库连接，不自动重试写入。
- 本地测量只用于前后对比，不能冒充生产 CPU 指标。

## Review focus
- 清空结束时间后保留开始时间。
- 冲突拒绝时整笔事务回滚。
- 旧版本重复提交被拒绝。
- 不同账号及并发请求不能串数据。
- 保存发生异常时保留表单和明确提示。

## Execution record (2026-10-21)
- 采用既有工作目录完成；用户已明确选择免费优化并授权发布，无新增审批。
- 本地 workerd 采样定位到 Prisma 编译、PostgreSQL 认证和 vinext 请求管线。
- 修复：冲突查询改为数据库范围筛选并只返回首个 id；允许冲突时不查询；投递读取/写入只返回实际需要的字段。
- 仅 `/api/data` 的完整 JSON 请求复用已断开连接的客户端，保留 WASM 构造器；并发各用独立客户端，所有请求仍关闭连接。页面、其他 API 和定时任务保持原生命周期，避免影响流式返回。
- `/api/data` 在请求上下文内动态加载既有 GET/POST，保留鉴权、来源检查、事务并设置 no-store。静态导入会过早初始化 auth，已弃用。
- 本地模拟器对尚未读取的大请求体提前返回 401/400 后可能中断后续连接；鉴权拒绝用小请求验收，正常保存另测 12000 字符中文 JD，均通过。
- 30 次同样的新建投递+日程：基线采样活跃时间 455.663ms，中位响应 15.137ms；最终组合 366.893ms / 12.380ms。约减少 19.5% / 18.2%。这是带分析器的本地采样，不等同生产计费 CPU，不能证明线上每次低于 10ms。
- 本地 Workers 验收：未登录拒绝、跨用户隔离、来源检查、新建、清空结束时间、提醒替换、冲突完整回滚、允许冲突、并发旧版本拒绝、完成后状态同步、相邻时间边界均通过。
- 单元测试 167/167 通过，类型检查通过，生产构建通过；发布和线上实际保存验证待完成。
