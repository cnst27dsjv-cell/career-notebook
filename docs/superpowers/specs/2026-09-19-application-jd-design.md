# 投递记录 JD 字段设计

## 目标

在新增和编辑投递记录时保存完整岗位描述（JD），为后续通过招聘截图自动识别并填写投递信息提供稳定的数据字段。

本次仅实现 JD 的手动录入、保存、读取和导出。多图片上传、图片留存和 AI 识别将在下一阶段实现。

## 交互设计

- 在“新增投递”和“投递详情”表单中增加“岗位描述（JD）”输入区。
- 输入区位于“职位链接”之后、“备注与下一步”之前。
- 使用完整宽度的多行文本框，默认显示 6 行，允许继续拉伸和滚动。
- JD 不是必填项；没有 JD 时仍可保存投递记录。
- 编辑已有投递时显示已保存的完整 JD，用户可继续修改。
- 保存失败时沿用现有表单错误提示，不清空用户正在编辑的内容。

## 数据与接口

- `Application` 数据模型增加非空字符串字段 `jd`，默认值为空字符串。
- 新增数据库迁移，为现有记录补充空字符串，因此不会影响已有投递。
- 前端 `Application` 类型增加 `jd`。
- `application.save` 接口接收并校验 `jd`，最大长度沿用现有长文本限制 100,000 字符。
- 工作台数据接口自动返回 `jd`；JSON 与 ZIP 备份自动包含该字段。
- 投递 CSV 导出增加“岗位描述（JD）”列，并继续使用现有的 CSV 注入防护和转义规则。

## 验证标准

1. 新建投递时填写 JD，保存后重新打开记录，内容完整保留。
2. 编辑已有投递的 JD 后再次打开，显示最新内容。
3. 未填写 JD 的新旧记录均能正常读取和保存。
4. CSV、JSON 与 ZIP 导出包含 JD。
5. 类型检查、现有单元测试、Next.js 构建和 Cloudflare 构建通过。

## 后续阶段边界

下一阶段将增加多张图片上传、原图附件保存、多模态 AI 提取和表单预填。AI 只预填截图中明确存在的公司、岗位、城市、招聘批次、职位链接和 JD，不修改投递阶段、阶段状态、投递时间、结果、简历版本或备注；用户确认后才保存。
