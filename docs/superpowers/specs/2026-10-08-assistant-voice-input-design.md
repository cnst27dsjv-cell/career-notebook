# AI 助理语音输入设计

## 目标

在 AI 助理的消息输入框中增加语音转文字入口。用户点击麦克风后说话，识别结果进入现有输入框，用户可以修改并手动发送。功能不自动发送消息；本站不保存或上传原始录音，但浏览器可能将语音发送到其在线识别服务。

## 范围

- 在现有助理输入框内增加麦克风按钮。
- 使用浏览器提供的 `SpeechRecognition` 或 `webkitSpeechRecognition` 能力完成中文语音识别。
- 默认语言设为 `zh-CN`，识别结果允许包含英文公司名、岗位名和专业术语。
- 将最终识别文字追加到输入框已有内容之后，不覆盖用户已输入的文字。
- 不支持语音识别的浏览器继续保留普通输入，并提示用户可使用系统键盘的语音输入。

本次不增加服务端语音模型，本站不上传音频、不保存录音，也不实现音频消息或连续语音对话。

## 交互设计

麦克风按钮位于消息输入框内、发送按钮之前，保持现有信纸风格。按钮有以下状态：

1. **可用**：点击开始识别。
2. **正在聆听**：按钮使用酒红色强调和轻量动态提示；再次点击可停止。
3. **不可用**：浏览器不支持时按钮不显示，输入区域附近提供一次简短说明。
4. **错误**：权限被拒绝、未检测到语音或识别服务失败时，在输入框附近显示可恢复的中文提示，不清空已有文字。

识别结束后，文字停留在输入框中并自动聚焦。用户检查或修改后，使用现有发送按钮提交。发送过程中沿用现有禁用规则，不允许同时启动语音识别。

## 数据与隐私

- 应用自身不创建音频文件，不把录音写入数据库或 R2。
- 语音识别由当前浏览器及其提供的识别服务完成；界面说明中避免承诺完全离线。
- 只有用户最终点击发送后，输入框中的文字才进入现有 AI 对话流程并保存为聊天记录。

## 代码边界

- 新增一个小型客户端 Hook，负责浏览器能力检测、识别生命周期、结果回调和错误归一化。
- `components/assistant.tsx` 只负责按钮、状态提示，以及把识别文字合并进现有 `input` 状态。
- 样式仅补充麦克风按钮和聆听状态，不调整助理页面的其他布局。
- 浏览器专有类型放在 Hook 内部，避免把兼容代码散落到对话组件。

## 错误处理

- 权限拒绝：提示在浏览器设置中允许麦克风，用户仍可键盘输入。
- 浏览器不支持：不阻断对话，提示使用系统键盘语音输入。
- 没有识别到内容：保留原输入并提示重新尝试。
- 识别过程中组件卸载、开始发送或再次点击：安全停止识别并释放引用。
- 识别服务异常：显示短提示，允许立即重试。

## 验收标准

- 支持的桌面浏览器中，点击麦克风可以开始和停止识别。
- 中文识别结果追加到已有输入，不覆盖文字且不会自动发送。
- 用户可以修改识别结果并通过原发送按钮提交。
- 权限拒绝、无语音、服务失败和不支持场景不会导致输入内容丢失。
- 页面离开或发送消息时不会留下仍在运行的识别会话。
- 语音输入不新增数据库字段、文件上传或服务端音频请求。
- 助理现有文字输入、文件附件、联网搜索和消息发送行为保持正常。

## 验证

- 为识别结果合并、状态切换和错误映射补充必要的单元测试。
- 运行现有测试与 TypeScript 检查。
- 在桌面 Chrome 中手动验证授权、开始、停止、修改和发送流程。
- 用手机页面尺寸检查按钮布局；在不支持的环境确认回退说明清楚且不阻断输入。
