# 助理文件正文与对话附件设计

日期：2026-10-08

## 1. 目标与验收标准

让求职助理在用户明确选择文件后读取正文，同时保留当前“最少必要上下文、来源可追溯”的边界。

首期完成以下能力：

1. 在聊天输入区增加“文件”入口，与现有“招聘截图 / 链接”并列。
2. 用户可以选择账号内已有的某一版简历，也可以上传 PDF、DOCX、TXT。
3. 文件只解析一次；同一文件后续使用缓存的正文，不重复下载和解析。
4. 发送前显示文件名、类型、解析状态和移除按钮；未解析成功的文件不能随消息发送。
5. 助理回复列出实际使用的文件来源，不能声称读取未选择的文件。
6. 新上传文件默认只在当前对话可用；用户可以明确选择“以后也能选择”，使其出现在后续对话的文件列表中。
7. 现有简历原文件、下载和版本管理行为保持不变。

不包含图片 OCR、PPT、Excel、旧版 DOC、压缩包、向量数据库，也不自动读取账号里的全部文件。

## 2. 方案比较与决定

### A. 把提取正文直接拼进用户消息

改动最少，但正文会污染聊天记录，长文容易超过单条消息限制，后续追问只能拿到被截断的历史内容。不采用。

### B. 每次模型调用时下载并重新解析原文件

不需要缓存字段，但响应慢、重复消耗资源，Cloudflare 执行时间和内存风险更高。不采用。

### C. 上传或首次选择时解析一次，消息只保存文件引用

正文与聊天展示分离；后续追问可继续使用同一来源；可以做大小限制、归属校验和来源展示。采用此方案。

## 3. 交互设计

聊天输入区保留“招聘截图 / 链接”，旁边增加“文件”。点击后打开一个轻量弹窗：

- “已有文件”列出未归档的简历，显示系列、版本、是否当前版、目标岗位和文件名；用户必须手动勾选具体版本。
- “上传文件”支持点击选择或拖入 PDF、DOCX、TXT，可连续添加多个文件。
- 每个文件显示 `等待解析 / 可使用 / 解析失败`。失败项显示可执行的原因，例如“扫描版 PDF 没有可复制文字，请改用截图识别或粘贴文字”。
- 新文件默认标记“仅当前对话”；勾选“以后也能选择”后才进入跨对话文件列表。
- 确认后附件以小标签出现在输入框上方。发送消息时附件和文字一起提交；附件可以在发送前移除。

文件不会因为选中就立即发送给模型。用户发送消息后，服务器才把本轮选中的正文加入模型上下文。后续追问默认可以继续使用当前对话最近明确使用过的附件；助理在答案来源中显示文件名。新建对话不会自动沿用仅当前对话的附件。

## 4. 数据与接口

扩展 `FileAsset` 保存解析状态、解析后的纯文本、解析时间、解析器版本，以及是否允许跨对话复用。原文件仍存 R2，数据库只保存文本和元数据。

为助理消息增加受控的附件引用，记录文件 ID、发送时的文件哈希和展示名称。模型输入只接受服务端按当前用户校验过的文件 ID，客户端不能直接提交任意正文冒充已上传文件。

文件接口分为三步：

1. 列出当前用户可选择的已有简历和可复用文件。
2. 上传并解析新文件，返回文件 ID 和解析状态。
3. 发送助理消息时提交所选文件 ID；服务器验证归属、状态和数量后组装上下文。

每次消息最多 5 个文件；单文件仍限制 10 MB。模型实际读取的附件正文设总字符预算，并按本轮问题选择相关片段；若正文被截断，回复中明确标注。原文件中的文字一律视为资料，不能改变助理的操作权限或确认规则。

## 5. 正文提取

提取实现必须兼容 Cloudflare 运行环境，不依赖本机命令、临时目录或外部办公软件：

- TXT：校验 UTF-8 后直接读取。
- DOCX：读取文档 XML 并提取纯文本，拒绝异常压缩体积和无正文文件。
- PDF：只提取已有文字层；扫描版不在本期做 OCR，提示用户改用现有截图识别入口。

解析后的文本去除空白噪声但不改写事实。解析失败不保存为可用附件；错误信息不暴露存储路径或内部堆栈。

## 6. 助理上下文规则

上下文优先级为：本轮明确选择的文件、当前对话最近使用的文件、匹配的业务记录和资料库节选。简历仍优先使用投递记录绑定的版本；若用户本轮选择了另一个版本，助理必须说明两者不同并询问使用哪一版，不能静默替换。

附件来源加入现有 `sourceIds` 白名单。回答只可引用实际送入模型的文件，并显示文件名和版本。没有正文时继续明确说明“未读取正文”，不能依据元数据猜测经历。

## 7. 隐私与生命周期

- 所有文件查询、下载、解析和消息关联都校验 `userId`。
- 联系方式等内容仅在用户主动选择文件并发送消息后进入模型请求。
- “仅当前对话”文件随对话保留，删除对话时同时删除没有其他引用的原文件和提取文本。
- “以后也能选择”的文件保留到用户主动删除；删除前说明仍引用它的对话。
- 日志只记录文件 ID、大小、解析结果和耗时，不记录正文。

## 8. 错误处理与验证

需要覆盖以下验证：

1. 非本人文件 ID、已删除文件和解析失败文件不能进入模型上下文。
2. PDF、DOCX、TXT 成功提取；扫描 PDF、伪造扩展名、超限文件显示明确错误。
3. 同一文件重复选择不会重复解析或重复加入上下文。
4. 选择特定简历版本后，助理来源显示正确版本；未选择时仍显示未读取正文。
5. 附件正文中的指令不能绕过草稿确认和操作白名单。
6. 手机端能选择文件、查看状态、移除附件并发送。
7. 普通无附件聊天、招聘截图 / 链接、简历下载及两套构建保持正常。

## 9. 实施边界

本改动只打通“选择文件—解析—随消息使用—显示来源”。不在本次新增全文搜索页面、自动给简历打标签、材料自动入库或经历事实画像。跨对话复用文件只提供选择和删除入口，不扩建独立文档管理模块。
