# 面试资料完整拆分与归档设计

## 背景

当前“助理拆分与分类”会把整份文档一次发送给模型，并要求模型重新输出全部正文。对于包含多套自我介绍、岗位知识和大量问答的长文档，模型可能合并条目、漏掉段落或因输出长度中止。系统目前也没有检查模型结果是否覆盖全部原文。

本次改动的目标是让上传内容可追溯、可校对且不静默丢失，同时继续以低成本模型完成大部分分类。

## 归档分类

资料按两级类目保存：

| 一级类目 | 二级类目 | 内容范围 |
| --- | --- | --- |
| 岗位特有 | 自我介绍 | 面向特定岗位的自我介绍；不同岗位、时长或版本分别保存 |
| 岗位特有 | 求职动机 | 为什么选择该岗位、公司或行业等依赖具体岗位背景的问题 |
| 岗位特有 | 岗位相关专业问题与知识点 | 岗位职责、流程、行业知识、工具、法规和专业问题及回答 |
| 岗位特有 | Case | 案例题、分析过程与作答内容 |
| 岗位特有 | 其他 | 与岗位相关但不属于其他岗位特有二级类目的内容 |
| 通用问题 | 个性问题 | 个性特点、优势短板和个人偏好等可跨岗位复用的问题 |
| 通用问题 | 行为面试 | 经历复盘、冲突协作、压力、失误和领导力等行为问题 |
| 通用问题 | 其他通用问题 | 可以跨岗位复用、但不属于以上类别的问题及回答 |
| 待确认 | 边界或分类待确认 | 无法可靠识别边界、岗位或类别的原文片段 |

每道问题及其回答作为一条资料。每套自我介绍作为一条资料。知识内容按完整主题保存，Case 按完整案例保存。

## 处理流程

1. DOCX 继续由服务器提取文字，但同时保留段落顺序和 Word 标题层级。
2. 本地解析器根据标题样式、岗位标题、问题编号、问号、空行和常见版本标记识别候选片段。解析器只划分边界，不改写正文。
3. 将候选片段分成小批次交给模型。模型只返回片段编号、岗位名称、一级类目、二级类目、标题和置信度，不重复生成正文。
4. 服务器用片段编号取回原文并组合结果，因此模型无法通过省略输出删除正文。
5. 没有被分类、模型返回无效编号、置信度过低或边界不明确的片段进入“待确认”。
6. 预览页允许修改岗位、一级类目、二级类目、标题和正文，也可以取消选择。
7. 用户确认后才写入资料库。

## 数据与接口

导入预览项包含：

- `sourceIndex`：原文片段的稳定序号。
- `roleScope`：识别出的岗位或方向；未知时为空。
- `category`：`岗位特有`、`通用问题` 或 `待确认`。
- `kind`：对应二级类目。
- `title`：原问题、版本名称或知识主题。
- `content`：由服务器按 `sourceIndex` 放回的原文。
- `confidence`：模型分类置信度，仅用于决定是否进入待确认。
- `selected`：是否入库。

资料库存储需要保留一级类目和岗位范围。已有资料若没有这些字段，读取时按原有 `kind` 推断；无法推断的显示为“待确认”，不自动改写历史正文。

## 模型调用

导入分类默认使用低成本模型。提示词明确给出分类枚举、少量示例和以下约束：

- 每个输入片段必须恰好返回一次。
- 只能引用输入中的片段编号。
- 不输出或改写正文。
- 无法判断时选择“待确认”。

每批设置固定片段数和字符上限。接口检查 HTTP 状态、JSON 结构、模型结束原因、编号重复及编号遗漏。单批失败时只重试该批；重试仍失败则把该批全部标为待确认。

## 完整性保证

服务器在返回预览前执行以下检查：

- 每个非空原文片段都出现在一个预览项中。
- 每个预览项正文都来自原始提取结果。
- 模型返回的编号不得重复、越界或缺失。
- 统计原文字符数、已分类字符数和待确认字符数。

页面展示“已覆盖全部原文”或明确显示待确认的片段数量和字符数。系统不得在覆盖不完整时显示导入成功。

## 界面行为

拆分预览顶部显示原文片段数、已分类数和待确认数。列表按“岗位范围 → 一级类目 → 原文顺序”展示，每条都可以展开核对。待确认项默认选中并醒目标记，避免用户忽略原文；用户可以编辑后入库或主动取消。

资料库采用三级浏览结构：

1. 首页按适用岗位生成卡片，岗位卡片与“通用”“待确认”处于同一层级。
2. 进入岗位后显示自我介绍、求职动机、岗位相关专业问题与知识点、Case、其他等二级类目卡片；进入“通用”后显示个性问题、行为面试、其他通用问题。
3. 进入二级类目后显示具体资料卡片。页面顶部用“资料库 > 岗位 > 二级类目”和返回按钮表示当前位置。

岗位卡片从资料的适用岗位动态生成，并提供“新建岗位分类”入口。适用岗位输入框列出已有岗位供选择，同时允许输入新岗位；保存新岗位资料时自动建立对应岗位卡片。空岗位分类需要持久化；以后导入或手动新增该岗位资料时继续复用同一卡片。“通用”和“待确认”是固定入口。

本次不新增独立主栏目，也不改变资料库的整体视觉风格。

## 错误处理

- 文档无法提取：保留当前明确错误信息。
- 某批模型超时或格式错误：重试一次，随后归入待确认。
- 模型因长度中止：视为该批失败，不接受部分结果。
- 全部模型调用失败：仍返回按本地规则划分的片段，统一标记为待确认，用户可以手动整理。
- 用户关闭预览：不写入资料库。

## 验收标准

1. 使用 `面试表述.docx` 导入时，文档从开头到第 42 题的非空正文全部出现在预览中。
2. 多套自我介绍分别形成资料项，不被压缩成一句话。
3. 编号面试题与紧随其后的回答保持在同一资料项中。
4. 岗位专业问题、岗位知识、Case、求职动机、个性问题和行为面试可以按上述类目归档；求职动机属于岗位特有，个性问题属于通用问题。
5. 无法可靠分类的内容进入待确认，不会丢弃。
6. 模型输出中止、漏号、重复编号或格式错误不会产生“完整导入”的假象。
7. 小批分类使用低成本模型；本次不要求切换为润色模型。
8. 原有“作为一份资料整理”入口继续可用。
9. 资料库首页按动态岗位、“通用”和“待确认”展示卡片；新增空岗位分类后刷新仍然存在。
10. 进入顶层卡片后先看到对应二级类目，再进入具体资料列表。

## 测试

- 为本地分段器测试岗位标题、多套自我介绍、编号问题、问题回答边界和无标题段落。
- 为模型分类结果校验测试漏号、重复号、越界编号和低置信度。
- 使用固定模型响应测试多批合并、单批失败回退和覆盖率统计。
- 用 `面试表述.docx` 做本地集成验证，检查首段、末段以及第 42 题均存在于预览结果。
- 运行现有测试、类型检查和生产构建。
