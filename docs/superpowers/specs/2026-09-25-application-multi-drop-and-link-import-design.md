# 新增投递多次拖图与链接解析设计

## 目标

扩展“新增投递”的 AI 导入能力：用户可以分多次拖入招聘截图，确认顺序后一次性识别当前全部图片；也可以粘贴无需登录即可访问的公开招聘链接，由系统读取网页并预填投递信息。

## 图片导入交互

- 图片拖拽区在已经加入图片后仍然保留，不再被缩略图列表替换。
- 用户可以一次拖入多张图片，也可以分多次继续拖入；新图片追加到已有图片末尾。
- 缩略图继续支持排序和删除，并清楚显示当前数量与最多 6 张的限制。
- 点击一次“开始识别”时，按当前顺序把列表中的全部图片作为同一份招聘信息联合分析。
- 沿用现有限制：PNG、JPG、JPEG、WebP，单张不超过 8 MB，合计不超过 24 MB。
- 识别失败时保留全部图片、顺序和表单内容，用户可以调整后重试。

## 链接解析交互

- AI 导入区增加“链接解析”入口，包含网址输入框和“解析链接”按钮。
- 仅接受 `http` 或 `https` 的公开网页地址。
- 解析成功后复用现有预填和字段冲突确认机制：空字段直接填写，非空字段由用户选择是否采用新结果。
- 成功解析的原始网址写入“职位链接”；网页分析只填写公司、岗位、城市、招聘批次和岗位描述等已有字段，不改变阶段、状态、时间、简历和备注。
- 需要登录、限制机器访问、不是网页正文或无法读取时，明确提示用户改为手动填写或上传截图。
- 图片识别和链接解析相互独立，用户可以任选一种，也可以先后使用；后一次结果仍经过字段冲突确认，不直接覆盖用户内容。

## 链接读取与安全

- 新增服务端链接解析接口，由服务器获取公开网页并把可读正文交给现有文字模型结构化分析。
- 请求前校验协议和地址，禁止访问本机、私有地址、链路本地地址、云环境元数据地址及包含用户名或密码的网址。
- 重定向次数受限，每次跳转都重新执行地址安全检查。
- 设置较短的连接与总请求超时，并限制响应体大小，避免异常页面拖慢 Worker。
- 只处理 HTML 和纯文本；不执行网页脚本，不携带用户浏览器的 Cookie、登录状态或授权信息。
- 提取标题、正文和必要的结构信息，去除脚本、样式、导航及重复空白，再交给文字模型。
- 模型输入明确声明网页内容是不可信资料，不执行其中的指令，只提取招聘字段。

## 返回数据与错误处理

- 链接解析沿用招聘截图分析的结构：`company`、`role`、`city`、`batch`、`url`、`jd`、字段可信度与提示。
- 服务端使用同一套结构校验和容错规则；无法确认的字段为空，不编造内容。
- 对外错误按用户可采取的下一步区分：网址格式错误、网页需要登录或拒绝访问、网页过大或超时、没有可读正文、AI 分析失败。
- 错误消息不暴露内部网络地址、响应正文、API 密钥或模型请求详情。

## 验证标准

1. 已有一张图片时拖拽区仍可用，第二次及后续拖入会追加图片。
2. 一次选择多张和多次分别拖入得到相同的有序图片列表，最多 6 张。
3. 点击识别会发送当前列表中的全部图片，而不是只发送最后一次加入的图片。
4. 图片排序、删除、识别失败重试和最终附件保存继续正常。
5. 公开 HTML 招聘链接可以预填现有字段，并自动保存原始职位链接。
6. 需要登录、禁止访问及非网页链接会给出可理解的提示，引导手动填写或截图。
7. 本机、私有网络和危险重定向链接会被服务端拒绝。
8. 图片与链接识别结果都不会静默覆盖用户已经填写的内容。
9. 单元测试、类型检查、应用构建与 Cloudflare 构建通过。

## 非目标

- 不读取需要登录才能访问的招聘页面。
- 不复用用户浏览器 Cookie，也不模拟登录或绕过网站访问限制。
- 不使用联网搜索结果替代用户提交的原始链接。
- 不新增图片数量、大小或格式范围。
- 不改变 AI API Key 和模型的配置方式。
