# 投递阶段与日历联动设计

## 目标

让待投递、测评、笔试和面试阶段可以直接在投递表单中安排日程，并由关联日程自动维护阶段状态，避免用户重复选择“待安排”“待完成”和“等待结果”。

## 阶段与日程映射

| 投递阶段 | 日程类型 | 是否显示安排区 |
| --- | --- | --- |
| 待投递 | 投递 | 是 |
| 已投递 | 无 | 否 |
| 测评 | 测评 | 是 |
| 笔试 | 笔试 | 是 |
| 面试 | 面试 | 是 |
| Offer | 无 | 否 |

同一投递、同一日程类型最多保留一项未完成日程。已完成或已取消的历史日程不限制后续再次安排，因此可以继续安排二面、三面。

## 自动状态规则

- 当前阶段没有对应的未完成日程时，状态为“待安排”。
- 当前阶段存在对应的未完成日程时，状态为“待完成”。
- 对应日程标记完成后：
  - 投递日程把阶段改为“已投递”，状态改为“等待结果”，并在没有实际投递时间时记录完成时间。
  - 测评、笔试或面试日程保留当前阶段，状态改为“等待结果”。
- 在“等待结果”阶段安排同类型的下一项日程时，状态重新变为“待完成”。
- 取消或删除当前阶段唯一的未完成日程后，状态恢复为“待安排”。
- 已投递固定显示为“等待结果”，不提供安排入口。
- Offer 隐藏阶段状态，其接受、拒绝等结果继续由“终止结果”表示。

阶段状态由服务端计算。客户端不提交任意阶段状态值，也不提供手动下拉选择。

## 表单交互

选择待投递、测评、笔试或面试时，在投递表单内显示“安排到日历”区域：

- 执行开始时间；
- 执行结束时间；
- 截止时间；
- 地点或会议链接；
- 提前一天、两小时、三十分钟提醒；
- 一个自定义提前小时数；
- 一个指定提醒时间；
- 允许与已有日程冲突的明确选项。

没有填写任何时间时保存为“待安排”，不创建日程。填写开始时间或截止时间后，投递与日程一次保存，并显示“待完成”。编辑投递时，安排区载入当前阶段已有的未完成日程。

切换阶段时，不自动删除旧阶段日程。旧日程继续保留在日历中，避免丢失已经安排的事项；如果旧日程仍未完成，表单应提示用户前往日历处理。新阶段只读取和编辑新阶段对应的日程。

## 服务端一致性

投递信息、关联日程和提醒任务在同一个数据库事务中写入：

1. 校验投递、简历和日程均属于当前账号。
2. 校验日程时间、自定义提醒时间及时间冲突。
3. 创建或更新当前阶段唯一的未完成日程。
4. 取消该日程旧版本尚未发送的提醒任务，并按新时间创建提醒任务。
5. 根据日程状态计算并保存阶段状态。
6. 记录阶段历史并递增版本号。

从日历单独创建或编辑已关联投递的日程时，也执行相同的状态重算。完成、恢复、取消和删除日程时同步更新关联投递，确保投递页、今日页、日历和助理读取到一致状态。

## 冲突与错误处理

- 与已有未完成日程重叠时，沿用现有冲突提示；用户明确允许冲突后才能保存。
- 已有同阶段未完成日程时更新该日程，不重复创建。
- 多设备同时修改时沿用版本校验，要求刷新后重试。
- 日程或提醒创建失败时整笔事务回滚，投递阶段不会单独保存。
- 删除或取消日程后，只根据当前阶段的同类型未完成日程重算状态，不影响其他阶段的历史。

## 数据与迁移

现有 `Application`、`Event` 和 `NotificationJob` 已包含所需字段，不增加数据库表或列。现有投递记录在读取和下次保存时根据关联日程重算状态；不会自动生成历史日程。

## 验证

- 待投递无日程为待安排，新增投递日程后为待完成，完成后变为已投递和等待结果。
- 测评、笔试和面试的新增、更新、完成、恢复、取消与删除均正确同步状态。
- 同阶段不会产生两个未完成日程，完成后可以安排下一轮。
- 时间冲突、提醒更新、账号隔离和多设备版本冲突保持有效。
- 桌面和手机表单均可完成安排，日历与今日页能立即看到新增事项。
- 全量测试、类型检查和 Cloudflare 构建通过。

## 非目标

- 不自动推断招聘方下一轮阶段。
- 不自动取消旧阶段日程。
- 不为已投递或 Offer 创建日程入口。
- 不改变终止结果的现有取值和用途。
