# 面试准备：现状核查与下一阶段建议

日期：2026-10-12。核查代码版本：`8a7a155`。

性质：问题审查与待讨论方案，不是已批准的实施计划。本轮未修改业务代码、数据库或线上配置，未使用个人面试资料调用外部模型。

## 1. 结论与证据边界

当前存在“助理升级了，但面试模块没有同步升级”的断层。模拟面试并非完全没有实现：已有独立界面、模型调用、逐题回答保存及确认入库；但联网入口仍依赖旧搜索方案，且完整面试教练、整场复盘和练习库持续更新尚未形成闭环。

本轮读取了原始 PRD、搭建计划、助理下一阶段方案及验收记录、搜索和文件正文设计，并检查当前源码及 Cloudflare Secrets 的名称。未读取密钥值；Secrets 存在不代表供应商调用有效，也未以真实账号复现线上报错。下述确定的是源码与配置之间的集成缺口，不把它泛化为对所有线上故障的解释。

## 2. 用户反馈逐项核查

### “调研并模拟面试”不能调研

调用路径：`components/preparations.tsx` 的 `research()` → `/api/ai` 的 `research` → `lib/model.ts` 的 `searchWeb()`。

该函数仍要求 `SEARCH_MODEL_API_KEY`、`SEARCH_MODEL_BASE_URL`、`SEARCH_MODEL_NAME`，请求 `/responses` 并携带 `web_search` 工具；错误信息及来源描述仍使用 Grok。

而“我的助理”使用 `/api/assistant` → `lib/tavily.ts` 的 `searchTavily()`。2026-09-28 搜索设计已明确采用 Tavily。Cloudflare Secrets 中可见 `TAVILY_API_KEY`，没有上述三个旧搜索密钥项；仓库 Wrangler 普通变量仅声明 `LOCAL_DEMO`。

这是最直接的失配。还存在第二个问题：搜索、出题、创建会话被串成一次请求，全部成功后才保存 Interview。搜索或出题失败会挡住此入口，也没有持久化调研报告可继续使用。现有“用自己的问题练习”是另一条可绕开的路径，不是此流程内部的恢复机制。

### “模拟面试界面和模型是不是没配置”

- 界面已经有：`components/interview.tsx`，支持逐题回答、上一题/下一题、反馈及确认保存。
- 出题已接 `generate()`，读取通用 `TEXT_MODEL_*` 配置。
- 反馈已接 `generate(..., "polish")`，优先使用 `TEXT_MODEL_POLISH_NAME`，缺失时回退通用模型。
- 云端上述配置的密钥项已存在；本轮未实际请求供应商，不宣称密钥额度或模型响应已验证。
- 不需要先额外购买或配置“模拟面试专属模型”才能修复入口。
- 当前出题上下文只有公司、岗位、JD、检索文本和来源；没有带入准备的轮次、关联简历正文和选择的练习材料。
- 当前反馈只传题目及本次回答，不包含完整对话、个人经历档案或已选资料。因此目前更接近固定题目练习与润色，而非能够深挖经历的面试官。
- 主助理的文件正文读取与语音输入没有自动扩展到模拟面试界面。

### “每次练习能否沉淀”

已有三层基础：

1. `Interview.questions/sources/turns` 保存题目、来源、回答、建议和确认状态；前端停止输入约一秒后提交草稿，也提供手动保存。
2. 确认后 `interview.confirm` 创建 `Material`，关联本次准备，记录模拟会话来源并保留原回答。
3. JSON/ZIP 导出已包含模拟面试和资料库数据。

尚缺：整场结束状态、当前进度恢复、整场总结、完整回答尝试历史、可操作的来源关系、关联到既有练习条目并新增修订、Markdown/Obsidian 交换。

保存回答时会将该题的 turn 重置为 `{answer}`，之前该 turn 的反馈/建议/确认标记不再保留；已经创建的 Material 不会因此删除。这意味着会话不是完整的不可变练习历史。再次入库也缺少选择“更新已有条目”的流程。

## 3. 与 PRD 和计划的差距

依据：`03_交付物/01_PRD.md` §3.7、`03_交付物/03_搭建计划.md` 阶段 6/7。

| 原定能力 | 当前实现 | 下一步补齐 |
| --- | --- | --- |
| 公司、岗位、JD、轮次调研 | 搜索只拼公司/岗位；旧搜索接口 | 统一搜索服务；提取公开岗位技能及轮次；私有经历不发送给搜索服务 |
| 可核对的调研资料卡 | 保存 URL/标题；日期均未知、描述通用；无独立报告 | 保存摘要、检索时间、来源类别及岗位/年份差异；明确摘要与全文边界 |
| 默认五题且可编辑 | 自动生成题目；另有手动建题入口 | 开始前选题、改题、调整顺序和难度 |
| 逐题回答、追问、跳过、结束 | 逐题回答与跳过已有 | 当前回答驱动追问；显式结束、暂停和继续 |
| 刷新恢复 | 已保存会话可从列表重开，题目索引从 0 开始 | 恢复到上次题目，区分草稿、进行中和已完成 |
| 当前题目加用户选择的资料 | 反馈只有题目和答案 | 使用关联简历版本正文、选择的材料、前文；显示实际读取的材料 |
| 反馈、缺失事实和逐字稿 | 文本反馈加润色建议 | 区分表达问题与缺失事实；保留专业术语，不虚构职责和数字 |
| 类似问题可新建或增加修订 | 每次确认主要创建新 Material | 候选匹配、差异审阅、用户选择更新或新建；保留完整版本 |
| 搜索失败可手动继续 | 独立手动入口存在；组合流程失败中断 | 调研与练习解耦；仅用 JD/个人材料练习时明确标为推测题 |
| 中文召回与真实来源验收 | 关键词匹配，先筛候选再排序；基础 CRUD 验收 | 完成原计划的 20 组检索样例和 10 组来源核对；补真实搜索→出题→反馈→入库验收 |

2026-09-25 助理下一阶段方案中的“面试教练与主动复盘”仍未完整交付。旧文档中“简历正文未实现”的结论已被 2026-10-08 文件正文功能部分更新，但该能力只接进主助理，不能据此视为模拟面试已接入。

之前把“代码中已有基础路径”当成“完整能力已可用”是不充分的。现有集成脚本测试的是手动建题、回答、重复确认幂等，没有调用真实 `research` 和 `feedback` 来证明组合流程。这次应按用户实际使用路径补验收。

## 4. Obsidian 的定位与三条路线

Obsidian 的库是本地 Markdown 文件夹。官方 URI 能打开、创建或追加笔记，但不能让云端网站凭一个链接直接读取整个本地库。官方现有 Headless Sync 可供自动化同步，处于 open beta，要求有效 Sync 订阅及运行同步客户端的环境；它也不是现有网站可直接调用的笔记 CRUD 接口。

### A. 站内保存为主，Markdown/Obsidian 交换为辅（推荐默认）

网站先可靠保存全部练习、原始回答、反馈和正式答案；支持选择条目导出 Markdown，导入 Markdown 时形成待确认改动。

优点：手机和电脑使用方式不变，无需额外同步服务即可形成练习闭环，也方便未来开源用户选择自己的笔记工具。代价：早期导入导出是显式操作，不是实时双向同步。

### B. Obsidian 是主要练习库，网站读取指定范围

适合已经大量使用 Obsidian 的情况。先选择文件夹或材料导入，网站保留来源与版本；模型提出更新，用户确认后写回指定笔记。

需要额外设计授权连接、正文同步、离线行为及冲突处理。电脑关机时不能把“本地插件在线”当成网站可用前提；可用云端的已授权副本继续练习，并标明同步时间。

### C. 一开始就全面双向自动同步

暂不推荐。必须处理两端同时修改、重命名、删除、重复导入、附件、同步失败、跨设备和账号隔离，容易让基础面试流程等待一个大工程。

无论选择哪条，连接笔记工具不会自动带来检索、版本管理或智能练习。需要独立完成“检索哪些材料、实际交给模型哪些内容、更新哪个条目、用户如何审阅差异”的产品机制。

若做交换，建议笔记包含稳定条目 ID、类型、公司/岗位、主题标签、来源会话、来源版本、更新时间。更新匹配依据 ID 和版本，不只看文件名或相似题目。导出整场复盘与导出正式答案应为两个独立选项，避免原回答被建议稿替换。

## 5. 建议的产品闭环

选择岗位/轮次及材料 → 核对调研摘要 → 调整练习题 → 逐题作答与追问 → 结束后复盘 → 确认新建/更新练习条目 → 下次按薄弱项复练。

信息分三层保存：

- **练习记录**：每次问题、追问、原始回答、反馈与发生时间。自动保存，可继续，不被正式答案升级覆盖。
- **正式练习库**：用户确认的可复用答案、经历和知识点，保存修订、来源与适用场景。
- **复盘与行动**：本次做得好/需改善的具体片段、待补事实及下次练什么；创建日程需确认。

反馈避免只有泛泛评分。优先指出具体原句、为什么不清楚、应补什么事实，以及一段保持专业术语、结构清晰、不太书面也不过度口语化的改写。数字和新经历必须来自用户提供的材料。

可进一步完善：

1. **两种练习模式**：教学模式每题立即反馈；模拟模式面试中不打断，结束统一复盘。
2. **围绕个人材料追问**：从真实项目中的职责、方法、依据、结果和反思逐层问；资料不足先澄清。
3. **主题与薄弱项积累**：标记“回答结构不清”“贡献边界不明”“结果缺证据”等可行动问题；下次针对性出题，不只重复随机题。
4. **同题进步对比**：并列原回答、上次确认稿与本次回答，显示证据充分度和表达改进，而非把模型分数包装成客观能力评价。
5. **实际面试复盘**：允许先记原话和零散回忆，再整理成题目、回答、追问、经验和后续行动；与模拟记录明确区分。
6. **复用现有语音输入**：先做语音转文字、核对后提交；语音合成和实时打断式对话作为后续可选项。原 PRD 曾排除语音视频模拟面试，不能把主助理语音入口的上线等同于该范围已批准。

## 6. 建议实施顺序与验收

### 第一批：恢复可用的面试练习

统一到现有 Tavily 与文本模型，调研可查看、失败可重试或跳过；用户可仅依据 JD/选定材料练习；展示实际使用的材料、来源和模型状态。

验收：从面试准备真实发起搜索→核对来源→生成题目→回答→反馈→确认入库→刷新恢复。另测未配置、额度不足、无搜索结果和模型失败，均不丢失已保存内容，不伪称完成调研。

### 第二批：完整面试教练与知识积累

选题、追问、结束与整场复盘；读入选定简历及资料；回答尝试历史；确认更新已有条目或新建；复练入口。先实现文字交互，再将主助理语音转文字复用到回答框。

验收：完整保存一场包含追问的练习；结束后可审阅总结；选择更新已有答案只增加版本；旧练习仍显示当时的回答；断网、重复确认、跨设备编辑冲突有明确反馈。

### 第三批：开放笔记交换和长期复练

根据用户现有练习库位置选择 Markdown 导入导出或 Obsidian 连接。先做可审阅、可回溯的单向交换，再由实际需求决定双向同步。加入按薄弱项建议复练、真实面试复盘和经确认的准备日程。

验收：同一笔记重复导入不重复创建；两端修改保留冲突稿，不静默覆盖；未选择的私人资料不被读取；用户能断开连接并明确保留/删除同步副本。
