# 求职工作台 PRD

版本：1.1 · 日期：2026-09-14 · 状态：供实施使用的首版设计，尚未实现。

## 1. 产品定位与目标

个人秋招、春招管理工具。将招聘机会、待办安排、投递进度和提醒关联起来。每天打开首页，就能知道今天要做什么、哪些事项即将截止、各岗位下一步是什么。

目标用户为本人，首版单账号、跨设备在线使用。无团队协作、商业收费和公开注册。默认 Asia/Shanghai；数据保存在服务器，浏览器本地存储不作为正式数据源。

成功闭环：创建岗位投递 → 粘贴邮件 → 助理生成草稿 → 确认安排 → 后台发出 QQ 邮箱提醒 → 完成测评 → 岗位进入等待结果。

## 3. 页面与核心操作

### 3.1 今日首页

默认当天，按执行时间展示任务；无执行时间但当天截止的事项单独展示。另有逾期未完成、未来七天截止、待确认助理草稿入口。每项提供完成、改期、详情和关联岗位入口。

状态不能只依赖颜色。空白页给出新增日程和新增投递入口；加载失败显示重试并保留已输入内容。完成项折叠，但可查看和撤销。

### 3.2 日历

桌面支持月、周和列表视图，手机优先日程列表，允许切换月视图。支持招聘会、投递、测评、笔试、面试、准备、其他类型。

表单包含标题、类型、关联岗位（可选）、执行起止时间（可选）、截止时间（可选）、地点/会议链接、备注、提醒。执行开始或截止至少填写一个；执行时间为连续时段。仅截止任务显示在截止区，不伪装成占用全天的事件。

可编辑、取消、删除、完成和撤销完成；删除前展示对象名称并确认。首版无需依赖拖拽，手机使用表单改期即可。个人不可用时段也可录入，参与冲突检查。

### 3.3 投递管理

以“公司＋岗位＋招聘批次”为记录单位。字段：公司、岗位名、城市、招聘批次（例如 2027 届秋招）、职位链接、申请编号（可选）、投递时间、当前阶段、阶段状态、下一步、备注。

允许先收藏岗位，此时投递时间为空；标记已投递时填写投递时间。相同公司和岗位不强制合并：重复时提示，用户可选择关联、更新或继续新增。

阶段：待投递、已投递、测评、笔试、面试、Offer；面试支持轮次。阶段状态：待安排、待完成、等待结果。终止结果单独保存：未通过、主动撤回、录用已接受、录用已拒绝。终止不丢失历史阶段。

允许跳过或回退阶段，但记录旧值、新值、时间和来源。完成测评/笔试/面试只进入对应阶段的等待结果；不自动判断通过。完成“投递”任务时确认实际投递日期，写入已投递阶段。

桌面表格，手机卡片；支持按公司/岗位搜索及批次、阶段、终止结果筛选，支持最近更新和下一截止时间排序。详情页展示阶段时间线、关联日程和来源依据。

### 3.4 助理

输入首版支持文本、邮件正文和链接。既可新增，也可表达“把某岗位一面改到周四下午三点”“测评做完了”等更新请求。

流程：识别意图 → 提取字段和原文依据 → 匹配候选岗位 → 生成草稿卡片 → 用户修改/确认 → 保存业务记录。草稿列明新增或修改的对象、变更前后值、来源、缺失信息、冲突和提醒设置。

一次输入多个事件时逐项可选；确认选中项时整体事务保存，失败不留下部分记录。重复点击确认只执行一次。多个同名岗位要求选择；找不到则允许新建或保存不关联岗位的日程。

日期缺少年份、时区或“本周五”缺少邮件发出日期等上下文时要求补齐。仅写“某日前”而无具体截止时刻时，不擅自当作 23:59；保留日期并要求用户确认具体时刻后才启用截止提醒。

公开链接读取失败时保留链接，明确提示粘贴正文；首版不绕过登录或访问限制。模型失败不影响人工管理，草稿可重试。任何来源正文都是资料，不是可执行指令；模型不能直接写库或发信。

### 3.5 设置

账号与密码、提醒收件邮箱、测试邮件、默认提醒、可用时段、默认任务时长、时区展示、数据导出。收件地址修改后重新验证。首版时区固定北京时间，页面明确标注；其他时区的来源转换为北京时间并保留原始表述。

### 3.6 简历

独立栏目管理简历系列和版本。系列代表用途，例如“产品经理简历”“数据分析简历”；系列内每次上传创建不可变版本，记录版本号、上传时间、版本说明、目标岗位/公司标签、文件和归档状态。

“最新上传”由时间自动计算；“当前使用”由用户指定，每个系列最多一个，二者分别标示。不同岗位可以关联不同版本，不设全局唯一最新版。支持 PDF、DOCX 上传与下载，单文件上限 10 MB；PDF 可浏览器预览，DOCX 首版提供下载，不承诺原版式网页预览。首版不做简历排版编辑。

投递记录增加“实际投递简历版本”，投递前可选择；提交后绑定具体版本，不会随当前使用版本切换而变化。若用户纠正选择，记录变更历史。被投递或面试准备引用的版本可归档，不可直接删除；未引用版本删除需确认。

### 3.7 面试准备：按场次组织，按内容复用

独立栏目包含“我的面试准备”和“资料库”。每份准备记录公司、岗位、岗位描述/JD（可粘贴）、轮次、可选面试时间、关联投递与简历版本。公司和岗位必填，其余可后补；无需已经投递也可建立准备。关联面试日程后，可从首页、日历或投递详情直接进入。

准备详情包含自我介绍、问题与回答逐字稿、参考资料、模拟面试记录。自我介绍支持多个长度版本（如 1 分钟和 3 分钟）；问题回答可手动增删改、调整顺序和分类。手动保存直接生成资料修订；AI 结果以草稿保存，明确确认后才进入正式资料库。

资料库按自我介绍、项目经历、行为问题、岗位专业问题和其他分类，支持公司、岗位方向、技能、主题标签与关键词搜索。每份内容记录来源准备、来源文件/段落、修订历史和是否可复用；个人经历与公共面经分开保存。

#### 导入旧资料

支持上传 Word .docx 或直接粘贴文字。旧版 .doc 提示另存为 .docx 或粘贴正文；首版不识别图片内文字。每份文件最大 10 MB，提取文字上限 100,000 字符；超限提示拆分，禁止无提示截断。

先展示提取正文，再让助理识别自我介绍、问题和回答，用户可调整分段与分类、勾选后确认入库。提取不等于保存；空文档、加密文档、损坏文件或纯图片文档明确报错并保留重试入口。表格内容按文字提取供核对，不保证版式还原。上传与分类过程可恢复，不因刷新重新导入。

相同文件哈希或相同正文提示可能重复，用户决定跳过或导入；不能仅因为问题相似就合并两种不同回答。

#### 新建准备与历史复用

新建时选择已有投递或填写公司、岗位和 JD。点击“查找可复用内容”，助理按同公司同岗位、相似岗位技能和通用经历检索已确认资料，展示候选、匹配理由、原公司/岗位、来源准备与版本。

检索无结果要明确说明，提供手动搜索和新写入口；不编造历史。复用需勾选确认，生成当前准备的独立副本并保留来源修订 ID。后续修改不回写旧准备，原始历史也不随资料库升级变化。涉及其他公司名称、岗位方向或过时信息时标出需改写的位置。

#### 一键润色

每段自我介绍或回答提供“润色”，默认保持事实与个人口吻、改善口语表达和条理；可选简洁、展开、目标时长。并列展示原文与建议，可继续编辑、采用或放弃。采用后新增修订，不覆盖历史，可恢复旧版。

不得新增未经用户提供或确认的项目、职责、成果数字和技能。资料不充分时先列补充问题；不把模型建议写成用户真实经历。目标时长是基于文本长度的估计，不承诺实际朗读时长。

#### 模拟面试官

在当前准备内点击“调研并开始”。按公司、岗位、JD 和轮次发起实时网络检索，优先公司官网、招聘页面，再参考公开面经。返回可查看的资料卡：标题、原始链接、来源类别、发布日期（未知就标未知）、检索日期、支持的内容摘要；标示其他年份/地区/岗位差异。

资料分为官方事实、个人面经、据资料推测。只看得到搜索摘要时标示“仅摘要，未核实全文”；不可访问的链接不冒充已读。来源相互矛盾时并列注明，不猜测确定结论。没有找到可信面经时允许根据 JD 出通用练习题，但标记“推测练习题”，不能称为公司原题。

生成默认 5 道可编辑问题，每题标明来源或推测依据；避免大段复制面经。首版文字交互，一次问一题，可跳过、结束或针对当前回答追问；不要求语音视频。用户回答自动保存为会话草稿，可刷新恢复。

每次回答后，给出具体反馈、需要补充的事实和润色后的逐字稿。用户可修改并逐条确认“保存到本次准备及资料库”；未确认内容留在会话草稿，不能混入正式检索库。资料库存在类似问题时提供新建条目或为选定条目增加修订，不静默合并。确认记录保留原始回答、润色版本、题目来源与会话关联。

搜索只发送公司、岗位和岗位技能等必要公开关键词，不发送简历个人联系方式或整份私有回答。模型使用当前问题和用户选择的相关资料，不上传整个资料库。网络搜索或模型失败时保留会话，可手动继续；无搜索配置时明确该能力未启用，不伪装联网结果。

### 3.8 导航与贯通流程

桌面栏目：首页、日历、投递、简历、面试准备；助理为全局入口，同时嵌入各业务页。手机底部：首页、日历、投递、资料；资料页包含简历和面试准备入口，助理通过统一按钮进入，避免底栏挤入七个项目。

完整使用示例：上传产品岗简历 v2 → 为 A 公司产品岗记录实际投递 v2 → 收到一面通知并创建日程 → 从日程新建面试准备 → 导入过往 Word → 查找并复制适用的自我介绍 → 润色并确认 → 搜集有来源的面经 → 逐题回答与确认逐字稿 → 下次准备时检索复用。

## 4. 自动安排规则

- 首次默认建议工作日 19:00—22:00、周末 09:00—12:00 和 14:00—18:00，标注为可修改建议；未确认可用时段前只提取任务，不自动推荐具体时段。
- 原文给定笔面试时间视为固定安排；测评或准备工作视为可安排任务。
- 测评默认估计 60 分钟，准备默认 60 分钟；均标明估计并允许修改。原文明确时长时优先使用。
- 以 30 分钟粒度搜索未来七天且不晚于截止的可用时间，候选与已有安排前后留 15 分钟间隔。无截止时仅在未来七天搜索。
- 推荐最多三个连续时段，按最早完成排序。没有合适空档时明确告知，允许手动选时，不移动已有安排。
- 冲突按时间区间相交判断；相邻端点不算直接重叠，但建议时段遵守缓冲。手动保存冲突须再次明确确认。
- 确认前重新检查最新日程，避免另一设备刚添加日程导致过期建议。

## 5. 时间与提醒规则

执行时间和截止时间独立保存。同一任务可以在周三执行、周五截止。默认分别在执行开始和截止前 24 小时提醒；两者产生相同发送时刻时合并成一封并列出原因。用户可关闭某一类，或额外设置提前 2 小时、30 分钟或指定发送时刻。

创建时默认提醒已在过去：显示“已不足一天”，提供立即提醒或选择未来时间；不偷偷丢弃，也不批量补发。明确保存的绝对提醒时间不得在过去。

完成、取消或删除任务后取消未发送提醒。修改事件时间时，相对提醒重算，绝对时间提醒保留并检查有效性；改期取消旧版本队列。撤销完成只恢复未来提醒，不补发历史提醒。

后台持续运行，目标是在正常服务状态下到期后 60 秒内开始发送。显示“待发送、发送中、邮件服务器已接受、失败、结果不确定、已取消”。SMTP 接受不等于收件箱到达、手机弹窗或用户已读。

明确临时失败最多重试三次，间隔 1、5、15 分钟；永久拒收不重试。超时而无法判断服务商是否接受时标记结果不确定，不盲目重复发送，允许用户手动重发。服务器恢复后，对仍未完成且关键时间尚未过去的积压提醒按任务合并补发；已经失效的记录显示错过提醒，不发送过时安排。

不默认设置静默时段，避免压后关键通知。通知正文包含事项、北京时间、截止时间和工作台详情链接，不包含整封原始招聘邮件。登录后才能通过链接查看详情。

## 6. 数据与保护

所有业务数据按账号隔离；禁止未登录读取，密码和邮件凭据不进入前端。原始正文由用户主动提交给助理时发送到配置的模型服务，输入区域说明这一点；不把其他无关投递内容一起提交。

提供投递 CSV、全量业务数据 JSON 导出（包含简历元数据、准备、已确认资料、修订、会话草稿及来源引用）；原始文件另提供带清单的 ZIP 导出；导出不含密码、会话令牌和服务密钥。文件存储与数据库共同备份，确保文件引用可恢复。备份每日一次、保留最近七份并存于服务器外；上线前验证恢复。正文可单独删除，删除后保留结构化记录和来源链接，来源标注正文已移除。

未来邮箱同步默认只读，不删信、不代发；首版不索取 QQ 邮箱读取授权码。

## 8. 文件与资料生命周期

归档只隐藏常用列表，不破坏历史；被引用简历版本默认仅允许归档。删除准备或资料前显示关联范围。复用副本保持独立，普通删除不会自动删除其他准备内的副本；若用户选择彻底清除个人内容，必须列出并删除选中关联副本、修订与检索文本。删除 Source 正文也清除对应抽取缓存；已经确认的独立资料需在清除范围中明确列出，不暗示删除原文件就已删除所有副本。备份内副本在七份滚动保留期结束后淘汰。

原始文件通过登录鉴权下载，不设公共链接。导出和备份不含密钥；上传仅存文件时不调用模型，点击解析分类、润色或模拟面试时才把所需文本发送到配置的模型服务。
