# 求职工作台 PRD

版本：1.0 · 日期：2026-09-14 · 状态：供实施使用的首版设计，尚未实现。

## 1. 产品定位与目标

个人秋招、春招管理工具。将招聘机会、待办安排、投递进度和提醒关联起来。每天打开首页，就能知道今天要做什么、哪些事项即将截止、各岗位下一步是什么。

目标用户为本人，首版单账号、跨设备在线使用。无团队协作、商业收费和公开注册。默认 Asia/Shanghai；数据保存在服务器，浏览器本地存储不作为正式数据源。

成功闭环：创建岗位投递 → 粘贴邮件 → 助理生成草稿 → 确认安排 → 后台发出 QQ 邮箱提醒 → 完成测评 → 岗位进入等待结果。

## 2. 范围与优先级

| 阶段 | 内容 |
| --- | --- |
| 首版必需 | 登录、今日首页、日历、岗位投递管理、手动增删改、阶段历史、完成状态、QQ 邮箱提醒、正文对话提取、确认卡片、空闲时段建议、数据导出 |
| 首版增强 | 尝试读取公开招聘链接；无法读取则要求粘贴正文，不阻断主流程 |

| 后续按需 | 系统日历同步、重复日程、附件识别、更多自动安排策略 |
| 当前不做 | 自动投简历、自动回复招聘方、模拟面试、简历编辑器、爬取全网岗位、多人协作、原生手机 App、离线编辑 |

## 3. 页面与核心操作

### 3.1 今日首页

默认当天，按执行时间展示任务；无执行时间但当天截止的事项单独展示。另有逾期未完成、未来七天截止、待确认助理草稿入口。每项提供完成、改期、详情和关联岗位入口。

状态不能只依赖颜色。空白页给出新增日程和新增投递入口；加载失败显示重试并保留已输入内容。完成项折叠，但可查看和撤销。

### 3.2 日历

桌面支持月、周和列表视图，手机优先日程列表，允许切换月视图。支持招聘会、投递、测评、笔试、面试、准备、其他类型。

表单包含标题、类型、关联岗位（可选）、执行起止时间（可选）、截止时间（可选）、地点/会议链接、备注、提醒。执行开始或截止至少填写一个；执行时间为连续时段。仅截止任务显示在截止区，不伪装成占用全天的事件。

可编辑、取消、删除、完成和撤销完成；删除前展示对象名称并确认。首版无需依赖拖拽，手机使用表单改期即可。个人不可用时段也可录入，参与冲突检查。

### 3.3 投递管理

以“公司＋岗位＋招聘批次”为记录单位。字段：公司、岗位名、城市、招聘批次（例如 2027 届秋招）、职位链接、申请编号（可选）、投递时间、当前阶段、阶段状态、下一步、备注。

允许先收藏岗位，此时投递时间为空；标记已投递时填写投递时间。相同公司和岗位不强制合并：重复时提示，用户可选择关联、更新或继续新增。

阶段：待投递、已投递、测评、笔试、面试、Offer；面试支持轮次。阶段状态：待安排、待完成、等待结果。终止结果单独保存：未通过、主动撤回、录用已接受、录用已拒绝。终止不丢失历史阶段。

允许跳过或回退阶段，但记录旧值、新值、时间和来源。完成测评/笔试/面试只进入对应阶段的等待结果；不自动判断通过。完成“投递”任务时确认实际投递日期，写入已投递阶段。

桌面表格，手机卡片；支持按公司/岗位搜索及批次、阶段、终止结果筛选，支持最近更新和下一截止时间排序。详情页展示阶段时间线、关联日程和来源依据。

### 3.4 助理

输入首版支持文本、邮件正文和链接。既可新增，也可表达“把某岗位一面改到周四下午三点”“测评做完了”等更新请求。

流程：识别意图 → 提取字段和原文依据 → 匹配候选岗位 → 生成草稿卡片 → 用户修改/确认 → 保存业务记录。草稿列明新增或修改的对象、变更前后值、来源、缺失信息、冲突和提醒设置。

一次输入多个事件时逐项可选；确认选中项时整体事务保存，失败不留下部分记录。重复点击确认只执行一次。多个同名岗位要求选择；找不到则允许新建或保存不关联岗位的日程。

日期缺少年份、时区或“本周五”缺少邮件发出日期等上下文时要求补齐。仅写“某日前”而无具体截止时刻时，不擅自当作 23:59；保留日期并要求用户确认具体时刻后才启用截止提醒。

公开链接读取失败时保留链接，明确提示粘贴正文；首版不绕过登录或访问限制。模型失败不影响人工管理，草稿可重试。任何来源正文都是资料，不是可执行指令；模型不能直接写库或发信。

### 3.5 设置

账号与密码、提醒收件邮箱、测试邮件、默认提醒、可用时段、默认任务时长、时区展示、数据导出。收件地址修改后重新验证。首版时区固定北京时间，页面明确标注；其他时区的来源转换为北京时间并保留原始表述。

## 4. 自动安排规则

- 首次默认建议工作日 19:00—22:00、周末 09:00—12:00 和 14:00—18:00，标注为可修改建议；未确认可用时段前只提取任务，不自动推荐具体时段。
- 原文给定笔面试时间视为固定安排；测评或准备工作视为可安排任务。
- 测评默认估计 60 分钟，准备默认 60 分钟；均标明估计并允许修改。原文明确时长时优先使用。
- 以 30 分钟粒度搜索未来七天且不晚于截止的可用时间，候选与已有安排前后留 15 分钟间隔。无截止时仅在未来七天搜索。
- 推荐最多三个连续时段，按最早完成排序。没有合适空档时明确告知，允许手动选时，不移动已有安排。
- 冲突按时间区间相交判断；相邻端点不算直接重叠，但建议时段遵守缓冲。手动保存冲突须再次明确确认。
- 确认前重新检查最新日程，避免另一设备刚添加日程导致过期建议。

## 5. 时间与提醒规则

执行时间和截止时间独立保存。同一任务可以在周三执行、周五截止。默认分别在执行开始和截止前 24 小时提醒；两者产生相同发送时刻时合并成一封并列出原因。用户可关闭某一类，或额外设置提前 2 小时、30 分钟或指定发送时刻。

创建时默认提醒已在过去：显示“已不足一天”，提供立即提醒或选择未来时间；不偷偷丢弃，也不批量补发。明确保存的绝对提醒时间不得在过去。

完成、取消或删除任务后取消未发送提醒。修改事件时间时，相对提醒重算，绝对时间提醒保留并检查有效性；改期取消旧版本队列。撤销完成只恢复未来提醒，不补发历史提醒。

后台持续运行，目标是在正常服务状态下到期后 60 秒内开始发送。显示“待发送、发送中、邮件服务器已接受、失败、结果不确定、已取消”。SMTP 接受不等于收件箱到达、手机弹窗或用户已读。

明确临时失败最多重试三次，间隔 1、5、15 分钟；永久拒收不重试。超时而无法判断服务商是否接受时标记结果不确定，不盲目重复发送，允许用户手动重发。服务器恢复后，对仍未完成且关键时间尚未过去的积压提醒按任务合并补发；已经失效的记录显示错过提醒，不发送过时安排。

不默认设置静默时段，避免压后关键通知。通知正文包含事项、北京时间、截止时间和工作台详情链接，不包含整封原始招聘邮件。登录后才能通过链接查看详情。

## 6. 数据与保护

所有业务数据按账号隔离；禁止未登录读取，密码和邮件凭据不进入前端。原始正文由用户主动提交给助理时发送到配置的模型服务，输入区域说明这一点；不把其他无关投递内容一起提交。

提供投递 CSV、全量业务数据 JSON 导出；导出不含密码、会话令牌和服务密钥。备份每日一次、保留最近七份并存于服务器外；上线前验证恢复。正文可单独删除，删除后保留结构化记录和来源链接，来源标注正文已移除。

未来邮箱同步默认只读，不删信、不代发；首版不索取 QQ 邮箱读取授权码。

## 7. 验收场景

| 编号 | 输入/操作 | 必须得到的结果 |
| --- | --- | --- |
| A01 | 电脑新建岗位，手机重新打开列表 | 同一记录可见，刷新仍存在 |
| A02 | 同公司两个岗位 | 独立日程和阶段，不误合并 |
| A03 | 邮件明确截止和时长 | 提取正确；确认前不写正式日程 |
| A04 | 缺年份或多个岗位匹配 | 提示补齐/选择，不猜测写入 |
| A05 | 无可用空档 | 显示无合适时段，不覆盖既有安排 |
| A06 | 双击确认或网络重试 | 只生成一组业务记录和提醒 |
| A07 | 完成面试 | 进入等待结果，未发送提醒取消 |
| A08 | 改期/完成/删除后旧提醒到期 | 不发送旧版本提醒 |
| A09 | 浏览器和个人电脑关闭 | 持续运行服务器仍触发邮件；真实 QQ 邮箱验收收件与手机通知 |
| A10 | SMTP 明确失败或超时 | 按重试/不确定规则处理，状态可见 |
| A11 | 另一设备更新草稿关联记录 | 检测版本冲突，要求刷新，不覆盖新值 |
| A12 | 公众号无法读取或模型不可用 | 可粘贴正文或手动添加，录入内容不丢失 |
| A13 | 未登录或使用其他账号对象 ID | 无法访问数据 |
| A14 | 导出和备份恢复 | 记录、时间线和未来提醒一致；恢复后不补发已发送任务 |

## 8. 后续扩展

QQ 邮箱同步在第二阶段单独验证 IMAP 接入、账号授权、增量游标、邮件 Message-ID 去重和重连恢复。识别结果先进入待确认收件箱，仍复用草稿确认流程。微信作为新增发送渠道复用同一提醒队列，绑定、额度和通知体验实测后上线。
