# 运行与部署说明

版本：本地首版 0.1 · 2026-09-14

## 1. 打开工作台

本机地址：http://127.0.0.1:3040 。双击项目中的 `启动求职手账.command` 可再次启动；Docker Desktop 需处于运行状态。

登录页提供两个入口：

- 示例手账：包含标明为示例的公司、日程和准备模板，供体验界面。
- 创建我的空白手账：首次建立个人账号，设置自己的登录邮箱和至少十位密码。账号建立后关闭新增入口的服务端能力；之后使用登录。

示例账号使用随机生成的本地密码，仅存在 `.env` 中，不提交到版本库。个人数据与示例数据按账号隔离。正式部署不开放示例和首次创建接口，使用受控脚本创建账号。

## 2. 日常使用路径

1. 在“投递”新增公司和岗位，选择城市、招聘批次、阶段和投递日期。
2. 上传简历，在投递记录里关联实际使用的版本。新的简历版本不会替换旧记录。
3. 在日历添加面试、测评或截止事项。可选提前一天、两小时、半小时、额外小时数或指定提醒时刻。
4. 从面试日程进入“面试准备”，关联公司、岗位和日程。
5. 面试资料可粘贴正文或上传 DOCX；先核对，再确认入库。旧 DOC 需另存为 DOCX。
6. 历史资料可检索复用；改写保留旧版本。配置模型后可润色，配置搜索与模型后可根据真实来源出题。
7. 可以先用自己的问题开始文字练习；停止输入一秒后自动保存，切题时也会先保存。AI 逐字稿需确认才进入资料库。

## 3. 提醒服务

当前 `.env` 为 MAIL_MODE=capture，邮件只进入本机 Mailpit 测试收件箱，地址 http://localhost:8026 。测试流程：保存收件地址 → 发送测试/验证邮件 → 在 Mailpit 中点击验证链接 → 添加未来提醒 → 查看发送记录。

网页与提醒进程分开运行。只关闭浏览器不会停止提醒；关闭电脑会停止本机进程，因此本地版不等于全天在线手机提醒。

真实发信需在本地私有配置中设置：MAIL_MODE=live、SMTP_HOST、SMTP_PORT、SMTP_SECURE、SMTP_USER、SMTP_PASS、SMTP_FROM。使用发送服务已验证的发件地址；接收地址在页面设置并验证，不需要读取 QQ 邮箱。

“邮件服务器已接受”只表示 SMTP 接受，不等于手机已弹通知。正式联调要分别检查 QQ 收件箱、垃圾邮件和手机通知权限。

## 4. AI 与联网服务

私有 `.env` 中配置 MODEL_BASE_URL（包含服务商要求的 /v1 前缀）、MODEL_API_KEY、MODEL_NAME。接口使用 Chat Completions 的 JSON 输出协议。当前提供：邮件正文提取日程、对话生成投递更新草稿、Word/正文拆分分类、回答润色、模拟面试反馈。

联网调研使用 Brave Search API，配置 SEARCH_API_KEY。它会检索公司、岗位和面经，保存真实返回的来源链接、摘要与检索时间。当前版本使用搜索摘要，页面标明未核实全文，不假装已经读过原网页；无来源题目标记为推测练习。

不将凭据填入公开文档、聊天记录或前端代码。修改配置后重启网页和 worker。无配置时界面如实提示，手动管理仍可使用。

## 5. 云端部署准备

已提供 Dockerfile、deploy/compose.production.yml、deploy/Caddyfile 和 deploy/production.env.example。尚未创建云服务器、绑定域名或上线。

1. 在可稳定访问的 Linux 服务器安装 Docker 与 Compose，将项目源码复制到服务器。
2. 参考 deploy/production.env.example 在项目根目录创建 `.env.production`，填写真实域名、数据库随机密码、认证 secret、SMTP 和所需模型/搜索配置。DATABASE_URL 与 POSTGRES_PASSWORD 保持一致。
3. 将域名指向服务器，再执行 `docker compose -f deploy/compose.production.yml up -d --build`。数据库健康检查通过后先执行迁移，随后启动 web 和 worker，Caddy 处理 HTTPS。
4. 通过受控命令运行 scripts/create-account.ts 建立个人账号：在服务器本地设置 NEW_ACCOUNT_PASSWORD，然后运行 `docker compose -f deploy/compose.production.yml exec -e NEW_ACCOUNT_PASSWORD web npx tsx scripts/create-account.ts`。不要运行示例种子。
5. 从手机和电脑分别登录；验证真实收件邮箱；在关闭网页和个人电脑后验证提醒送达。

镜像构建尝试在拉取 Node 基础镜像时遇到 Docker Hub 网络超时，未完成容器镜像验收。Next.js 本机生产构建已通过；两者是不同检查，不将前者说成已通过。

## 6. 备份和恢复

本地可运行 `./scripts/backup.sh`，生成 PostgreSQL dump 和原文件压缩包，保存在 storage/backups。当前提供按需备份，尚未配置每日自动异地备份和外部监控。

恢复演练已在单独的临时数据库进行，核对了投递数量；测试文件 ZIP 导出也单独通过。正式恢复时先停 worker，保留现有库和文件副本，导入到新数据库验证后再切换连接，核对已发送状态后恢复 worker。不要向真实使用中的数据库直接执行未经验证的覆盖恢复。

云端需将数据库及文件卷一起备份到服务器外，设置每日计划与七份保留策略，并至少做一次真实原文件恢复演练。本地备份并不具备异地灾备能力。

## 7. 运行定位

- 网页：本地 3040 端口；健康检查 `/api/health`。
- 数据库：项目专用容器，127.0.0.1:5544，独立 career-notebook_career-db 卷。
- 邮件捕获：127.0.0.1:1026，查看入口 8026。
- 上传文件：storage，鉴权后访问，不放在 public。
- 双击启动日志：06_临时文件/web.log、worker.log。
- 不使用 `docker compose down -v` 作为日常停止操作，它会移除数据卷。正常停止用 `docker compose stop`，网页和 worker 由各自进程管理。
